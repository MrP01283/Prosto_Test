# Просто Тест

Личный конструктор учебных тестов и публичное прохождение по ссылке. Работает на GitHub Pages без отдельного сервера, подписки и общей базы результатов. Начальный каталог пустой.

**Репозиторий:** https://github.com/MrP01283/Prosto_Test

**Адрес GitHub Pages:** https://mrp01283.github.io/Prosto_Test/

## Первый запуск

1. В репозитории откройте **Settings → Pages**.
2. В **Build and deployment → Source** выберите **GitHub Actions**. Если Pages уже настроен, повторять это не нужно.
3. В **Actions → Publish GitHub Pages** проверьте последний запуск. После успешного развёртывания откройте адрес сайта.
4. Нажмите **Для создателя → Создать тест**. Введите название, добавьте вопросы, затем проверьте их через **Предпросмотр**.
5. Нажмите **Опубликовать** и подключите GitHub, если он ещё не подключён. После сохранения сайт покажет постоянную ссылку на тест.

Каждый push в `main`, включая публикацию теста из конструктора, запускает проверку и обновление сайта. В сборку входят только `index.html`, `assets`, `src`, `data` и служебная страница 404. Макеты, исходники проверок и этот README в сборку не попадают.

## Доступ создателя

Конструктор можно открыть на компьютере и работать с локальными черновиками без подключения GitHub. Это полезно в том числе после истечения ключа. Локальные черновики не отправляются в репозиторий автоматически.

**Общедоступные тесты может менять только владелец `MrP01283` с правами записи в `Prosto_Test`.** Кнопка подключения проверяет GitHub-аккаунт и доступ к репозиторию. Реальное разрешение на публикацию обеспечивает GitHub, а не скрытая кнопка или пароль внутри JavaScript.

GitHub Pages раздаёт общедоступные файлы. Поэтому сама страница конструктора не является закрытой админкой: другой человек технически может открыть её и создать собственные локальные черновики в своём браузере. Изменить ваш публичный каталог без доступа к репозиторию он не сможет. На общем компьютере используйте отдельный профиль браузера: черновики и история доступны пользователям этого же профиля.

### Подключение GitHub

1. Откройте https://github.com/settings/personal-access-tokens/new под аккаунтом `MrP01283`.
2. Создайте **fine-grained personal access token**, задав понятное имя и срок действия.
3. В **Repository access** выберите **Only select repositories → Prosto_Test**.
4. В **Repository permissions** включите **Contents: Read and write**. Metadata: Read доступно автоматически. Для публикации тестов не нужны права Workflows, Administration или доступ к другим репозиториям.
5. Скопируйте ключ в окно **Подключить GitHub** на сайте.

Ключ хранится только в памяти текущей вкладки. Он не сохраняется в IndexedDB, localStorage, cookies, файлы сайта или коммиты. После обновления страницы нужно подключиться снова. Кнопка **Отключить** удаляет ключ из памяти приложения. Срок действия и отзыв ключа управляются в GitHub. Не присылайте ключ в чат и не добавляйте его в репозиторий.

Ключ с Contents: write даёт доступ к содержимому выбранного репозитория целиком, поэтому ограничивайте его именно этим репозиторием. Приложение отправляет ключ только на `api.github.com`. В приложении нет внешних скриптов, шрифтов, аналитики или рекламных сервисов.

## Создание и редактирование теста

- Прокрутка списка вопросов сохраняется при переключении между вопросами и обновлении конструктора.
- Тест начинается без вопросов. Название обязательно, описание необязательно.
- Каждый вопрос содержит только текст, минимум два варианта и ровно один правильный ответ.
- В новом вопросе создаётся пять пустых вариантов. Их можно добавлять и удалять без фиксированного максимума. Первый вариант выбран правильным; кружком слева можно выбрать другой.
- При удалении правильного варианта правильным становится первый оставшийся. Это видно в конструкторе; перед публикацией проверьте выбор.
- Вопросы можно переставлять стрелками, выбирать в списке слева и удалять.
- Черновик автоматически сохраняется примерно через 0,4 секунды после изменения. Статус сохранения расположен рядом с названием. Перед переходом, предпросмотром и публикацией приложение дожидается сохранения.
- Незавершённые вопросы допустимы в черновике. Предпросмотр и публикация проверяют название, заполнение вопросов, варианты и правильные ответы.
- **Создать отдельную копию** делает новый независимый черновик с новыми идентификаторами вопросов и ответов.

### Полный вопрос в одном окне

Кнопка **Вставить полный вопрос** добавляет вопрос. Кнопка **Заменить из текста** заполняет текущий вопрос заново.

Вставьте один вопрос и его ответы. Каждый ответ должен начинаться с новой строки. Поддерживаются латинские и кириллические буквы с `)` или `.`, а также простые строки без меток. При буквенных метках переносы внутри вопроса и ответа сохраняются. При вставке без меток первая непустая строка считается вопросом, следующие — ответами.

Галочка **Убирать номер вопроса и буквы вариантов ответа** включена по умолчанию. Она удаляет только метки в начале строк; числа внутри текста остаются. Предпросмотр показывает, что именно будет добавлено. Первый распознанный ответ становится правильным; после вставки его можно изменить. Если распознать блок не получилось, приложение показывает причину и не добавляет вопрос.

Импорт Word не реализован в соответствии с выбранным объёмом проекта. Можно копировать текст вопроса из любого документа в окно вставки.

### Перенос из другого теста

**Из другого теста** открывает список локальных и опубликованных тестов. Выберите источник, отметьте нужные вопросы или нажмите **Выбрать все**. Добавляются независимые копии с вариантами и правильным ответом.

Совпадение нормализованного текста вопроса считается возможным повтором. Приложение предложит добавить все выбранные вопросы или пропустить повторы. Изменение исходного теста не меняет копии.

### Количество вопросов и перемешивание

В настройках доступны все вопросы или случайная часть от 1 до общего количества минус 1. Для точного значения есть числовое поле рядом с ползунком.

В режиме «Все» доступна галочка **Разрешить выбор диапазона участнику**; по умолчанию включена. Она сохраняется вместе с опубликованным тестом. При выборе «Случайная часть» галочка выключается и становится недоступна, при возврате к «Все» включается снова. Для старых тестов без этой настройки выбор диапазона также включён, если используется режим «Все».

При разрешённом диапазоне вопросы внутри выбранных границ всегда перемешиваются перед прохождением; переключатель порядка вопросов в конструкторе недоступен. Перемешивание вариантов ответа по-прежнему настраивается отдельно. Если выбор диапазона отключён, действуют обычные переключатели.

Случайная часть всегда выбирается случайно и без повторов. Когда выбор диапазона выключен, два независимых переключателя управляют порядком вопросов и вариантов ответа; оба включены по умолчанию. Если перемешивание вопросов выключено, выбранная случайная часть показывается в порядке конструктора. Правильный ответ связан с идентификатором варианта и остаётся правильным после перемешивания.

Размер теста не ограничен 300 вопросами; проверка алгоритма включает 500 вопросов и более десяти вариантов ответа. Очень большие объёмы ограничиваются доступной памятью браузера, диском, размером файла GitHub и скоростью соединения.

## Публикация и ссылки

**Опубликовать** записывает только готовую публичную версию теста в `data/tests.json` через GitHub REST API. Создаётся обычный коммит в `main`. Файл каталога обновляется одной атомарной операцией; остальные тесты сохраняются.

Изменения существующего опубликованного теста сначала остаются локальным черновиком. Участники продолжают видеть последнюю опубликованную версию. Нажмите **Опубликовать правки**, чтобы заменить её. В диалоге показана ссылка вида `https://mrp01283.github.io/Prosto_Test/#/test/UUID`.

Ссылка не зависит от названия и остаётся той же при переименовании и редактировании теста, пока сохраняются репозиторий, адрес Pages и идентификатор теста. Хостинг не гарантирует абсолютную бесперебойность: возможны сбои GitHub, отключение Pages, ограничения аккаунта или удаление репозитория.

**Закрыть** оставляет тест в каталоге с пометкой «Закрыт». Прямая ссылка показывает сообщение о закрытии. **Открыть** возвращает доступ по прежней ссылке. **Удалить** убирает тест из каталога и удаляет его локальный черновик. Завершённые попытки у участников сохраняются, поскольку содержат собственные снимки вопросов и ответов.

Публикация, закрытие и удаление появляются у посетителей после успешного развёртывания GitHub Pages, обычно через несколько минут. Создатель видит результат записи в GitHub сразу, поэтому в первые минуты каталог у участника может ещё отличаться.

Перед записью приложение сверяет ревизию выбранного теста и SHA файла. Если тест или файл изменился в другой вкладке, устаревшая версия не записывается поверх новой. Обновите список, сравните правки и при необходимости создайте отдельную копию. Не редактируйте один локальный черновик одновременно в нескольких вкладках: локальное хранилище общее для одного профиля.

## Прохождение участником

Регистрация, пароль, ФИО и группа не требуются. Участник видит каталог опубликованных тестов с количеством вопросов и закрытыми тестами. Есть поиск по названию.

После открытия ссылки показывается число вопросов в попытке. Если создатель разрешил выбор диапазона, участник задаёт начальный и конечный номера двумя ручками ползунка или полями **От / До включительно**. По умолчанию выбраны все вопросы; кнопка **Все вопросы** сбрасывает границы. Отрицательные числа, дроби, значения за пределами теста и обратный диапазон не допускаются; при завершении ввода значение приводится к ближайшей допустимой границе.

Диапазон 50–100 — это ровно 51 вопрос с соответствующими позициями в конструкторе. Сначала выбираются эти позиции, затем перемешивается только выбранный набор. При прохождении и разборе виден исходный номер вопроса. Выбранные границы и исходное число вопросов сохраняются в результате и истории, даже если тест позднее изменён. Старые результаты остаются доступными без отметки диапазона. При обновлении страницы прохождение начинается заново в том же диапазоне, поскольку границы включены в адрес попытки.

Нажатие **Начать прохождение** запускает таймер прошедшего времени. Лимита времени нет.

- Правильный ответ выделяется зелёным, затем через 0,7 секунды открывается следующий вопрос.
- При ошибке выбранный ответ выделяется красным, правильный — зелёным. Переход выполняется кнопкой участника.
- Ответ можно дать только один раз; повторные клики во время проверки игнорируются.
- Обновление страницы во время прохождения создаёт новую попытку с нулевым временем: выбранный диапазон сохраняется и перемешивается заново; в режиме случайной части выбирается новый случайный набор. Незавершённые попытки в историю не записываются.
- Предпросмотр использует эти же правила, но не сохраняет результат в историю.

После последнего вопроса видны общее число вопросов, правильные и неправильные ответы, процент, время и подробный разбор. Переключатель показывает все вопросы либо только ошибки. В разборе отмечены выбранный и правильный варианты.

### Закрытие уже начатой попытки

Сайт проверяет доступ при старте, периодически во время выполнения, при ответах и перед завершением. Повторные проверки в течение десяти секунд объединяются, фоновая проверка выполняется каждые 30 секунд. После обнаружения закрытого или удалённого теста попытка прекращается и не сохраняется.

Это статический сайт: немедленное отключение уже загруженного теста до окончания публикации, во всех кэшах и без интернета невозможно. При недоступности сети прохождение приостанавливается с кнопкой повторной проверки. Уже загруженный код технически можно изменить в браузере. Сайт предназначен для самостоятельного обучения, а не для защищённого экзамена: правильные ответы присутствуют в публичных данных.

## История, черновики и темы

Черновики и завершённые попытки хранятся в IndexedDB (`prosto-test-v1`, таблицы `drafts` и `attempts`). Закрытие вкладки, браузера или перезагрузка компьютера обычно их не удаляет. У истории нет заданного срока истечения.

Данные не синхронизируются между устройствами, профилями, браузерами и адресами сайта. Данные локального предпросмотра на `localhost` не появятся на GitHub Pages. При очистке данных сайта, удалении профиля, работе в приватном режиме или автоматической очистке хранилища браузером данные могут пропасть. При создании черновика приложение запрашивает постоянное хранение через Storage API, если браузер это поддерживает; это не отменяет ручную очистку.

История включает снимок вопросов и выбранных вариантов на момент прохождения. Более позднее редактирование теста не меняет старый результат. Общей базы, отправки результатов создателю и экспорта в Excel нет.

Светлая тема включена по умолчанию. Кнопка солнца/луны меняет тему на всех экранах. Предпочтение сохраняется в localStorage; при недоступности этого хранилища переключение всё равно работает в текущей вкладке.

## Разработка и устройство проекта

Нужен Node.js 22 или новее. У приложения нет сторонних runtime-зависимостей и серверной части.

```sh
npm start       # http://127.0.0.1:8787/
npm test        # проверки логики и GitHub API с имитацией ответов
npm run build   # готовые статические файлы в _site/
```

Открывайте сайт через HTTP-сервер или GitHub Pages: ES-модули и загрузка JSON не предназначены для запуска двойным щелчком через `file://`.

| Файл | Назначение |
| --- | --- |
| `index.html`, `assets/app.css` | Каркас, две темы, адаптивная вёрстка |
| `src/app.js` | Маршруты, конструктор, модальные окна, прохождение и история |
| `src/core.js` | Парсер, валидация, копирование, выборка, подсчёт результатов |
| `src/storage.js` | IndexedDB и подтверждение завершённых транзакций |
| `src/github.js` | Проверка владельца, чтение каталога и публикация через API |
| `src/config.js` | Владелец, репозиторий, ветка, задержки |
| `data/tests.json` | Только опубликованные и закрытые тесты; изначально пусто |
| `.github/workflows/pages.yml` | Проверка, сборка и публикация Pages |
| `tests/` | Автоматические проверки; временные данные не попадают в сайт |
| `mockups/` | Согласованные макеты; отдельно от рабочего приложения |

Маршрутизация через `#/…` позволяет открывать прямые ссылки без серверных правил перенаправления. Тексты пользователей экранируются перед вставкой в HTML. Content Security Policy запрещает внешние скрипты и допускает сетевые запросы только к своему адресу и GitHub API. Сервис-воркер не используется, чтобы старый офлайн-кэш не задерживал закрытие тестов.

30–50 участников загружают статические файлы независимо друг от друга и сохраняют результаты локально. У сайта нет единого процесса обработки попыток или блокировки общей базы. Реальная доступность и пропускная способность зависят от лимитов GitHub Pages; отдельный нагрузочный тест внешнего GitHub не выполнялся.

## Если что-то не работает

- **Пустой каталог после публикации:** дождитесь зелёного запуска в Actions, затем обновите страницу. Закрытая или неуспешная сборка не обновляет сайт.
- **GitHub Pages ещё не включён:** Settings → Pages → Source → GitHub Actions, затем повторный запуск workflow.
- **Ошибка ключа:** проверьте аккаунт, срок действия, выбранный репозиторий и Contents: Read and write. Пароль GitHub вместо токена не подходит.
- **Конфликт публикации:** обновите список и сравните локальные правки с актуальной версией. Приложение не перезаписывает конфликт автоматически.
- **Черновик не найден:** проверьте, что открыт тот же адрес сайта, браузер и профиль. Локальные черновики не восстанавливаются из публичного GitHub.
- **Ошибка сохранения:** освободите место и разрешите данные сайта. Не закрывайте вкладку, пока нужные данные не сохранены.
- **Тест удалён, но старый результат есть:** это ожидаемо; история хранит снимок завершённой попытки.
- **При изменении `data/tests.json` вручную:** сохраняйте уникальные идентификаторы и правильные ссылки `correctOptionId`, обновляйте `revision`. Перед push запускайте `npm test` и `npm run build`.
